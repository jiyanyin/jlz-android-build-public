# 自动截图应用选择修复

本人报告：选择弹窗只有说明和保存按钮，没有应用列表；保存后显示零个应用。

原因：原生 AlertDialog 同时设置 setMessage 与 setMultiChoiceItems，说明占用了列表所在的内容区域。进入弹窗前已有非空候选检查，因此这次不是未查到可选应用。持久层把空选择成功写入并关闭截图，界面却显示保存成功。

修复版本：`0.6.5-world-between-local.7 / 2026101605`。

- 说明移到标题区域，内容保留原生可滚动多选列表，显示实时已选数量；重新打开回显已保存勾选。
- 零选择不能点击保存；取消不改变已有配置。保存失败保留弹窗，只有写入并读回一致才提示开启。
- 持久层拒绝空选择或全被安全过滤的开启请求，保留原有配置；暂停仍可保留选择。
- 设置页重新读取保存的开关和数量，避免从模式页回来仍显示旧计数。

不扩大可选范围、截图频率或敏感页权限；同包名和原签名覆盖安装，保留已有连接、门禁及私人素材。没有修改后端，不需要为此再次部署 Home Node。

验证：新增真实原生弹窗列表挂载／显示、选中后持久化与重开回显、取消、失败重试、大字体多应用列表以及空选择保护回归。完整私有CI、签名与实机状态待构建完成后更新，不能以测试代替手机验收。

Android 官方限制说明：[Dialogs](https://developer.android.com/develop/ui/views/components/dialogs)。
